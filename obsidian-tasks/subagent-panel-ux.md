## Body

**Зачем.** После interactive-child-sessions каждый `agent_spawn` открывает вкладку-сессию, строка spawn у родителя пустая, итог ребёнка приходит модели невидимым `<system-reminder>`, внимание уводит пользователя во вкладку ребёнка, списка агентов нет. Эталон — актуальный Claude Code (проверено по code.claude.com/docs/en/sub-agents 2026-09-06): сабагенты живут в панели под строкой ввода, а не во вкладках; `/tasks` для списка; результат приходит сообщением в основной разговор; permission-ask фонового сабагента всплывает в main с именем сабагента.

**Что остаётся как есть.** Ребёнок остаётся полноценной retained-сессией (Controller/View) — это и есть «detail pane» из Claude Code: Enter открывает его транскрипт, набор текста в нём = resume/steer. Меняется только представление: ребёнок не занимает вкладку по умолчанию и не тянет внимание пользователя к себе. Durable outcome/inbox (multisession-parent-inbox) не переделывается; добавляется только UI-событие.

**Контракт UI.**
1. *Строка в транскрипте родителя.* `explore(описание задачи)` вместо `agent_spawn`; при работе — `⟳ … · 12 tools · 1m20s` из job.Progress; после завершения — `✓ … · 12 tools · 1m20s` + итог (summary из outcome) под строкой; Enter/клик раскрывает дерево tool-вызовов ребёнка. Требует, чтобы interactiveRunner эмитил `env.OnProgress` так же, как EngineRunner (сейчас SubagentStore пуст).
2. *Панель под композером.* Показывается только когда есть живые дети: `● main`, ниже `○ explore(описание) · 12 tools · 1m20s`, вложенные дети деревом, скрытые потомки `(+N)`. Клавиши по DESIGN.md: ↑/↓ выбор, Enter — открыть транскрипт ребёнка (активировать его View, без вкладки), Esc — назад в родителя, x — остановить, →/← — раскрыть/свернуть. Вход в панель — `/tasks` или горячая клавиша из multisession-hotkeys; композер не теряет Enter.
3. *Жизненный цикл строки.* Успех → строка убирается сразу, футер 30 с: «/tasks — сабагенты». Ошибка/стоп → строка 30 с, `x` убирает раньше. Fake clock в тестах.
4. */tasks.* List pane по образцу watchpane: running сверху, done (окно 30 с и все retained дети сессии) ниже; Enter — транскрипт, x — стоп, Esc — закрыть. `⚙N` в селекторе и «N jobs» в футере остаются как есть.
5. *Итог в родителе.* Доставленный outcome рендерится локальной строкой транскрипта (как RoleWatch/RoleNotice), а не user-message: виден сразу и после resume (сейчас StripReminders его прячет). Текст модели остаётся тем же `<system-reminder>`.
6. *Permission-ask ребёнка.* Пока View ребёнка не открыт, ask ребёнка показывается в родителе с префиксом имени ребёнка; approve пропускает вызов, Esc отклоняет только этот вызов (ребёнок продолжает). Session-wide grant применяется и к main. Если View ребёнка открыт — ask там же, как сейчас.
7. *Селектор.* Дети не в табах. Attention от ребёнка (ask/ошибка) → строка панели + футер, не «/switch N».

**Фазы (каждая — своя ветка/worktree, реализуют Opus-субагенты).**
- A `subagent-row-progress`: OnProgress из интерактивного раннера, имя `role(описание)`, счётчики/elapsed, итог локальной строкой (п.1, 5).
- B `subagent-panel`: панель под композером, скрытие детей из селектора, Enter/Esc/x, таймеры, футер-подсказка (п.2, 3, 7).
- C `subagent-tasks-pane`: `/tasks` (п.4).
- D `subagent-ask-routing`: ask ребёнка в родителе (п.6).

**Не делаем.** Ctrl+B (все дети и так фоновые), pause по Space, лимит 20 (наш — 12 retained), fork/`/subtask` (отдельное решение), sidebar (multisession-sessions-panel остаётся deferred).
