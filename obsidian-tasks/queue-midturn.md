# queue-midturn

## Body

Queued-сообщение, отправленное во время агентного хода, доходит до модели
только после конца ВСЕГО хода (`finishRun`). В ходе на десятки tool-раундов
это минуты: строка висит с «(queued)», модель «игнорирует» сообщение.
Claude Code инжектит на границе tool-раунда — модель видит его в том же ходу.

## Solution

Шов `LoopOpts.Inject` в `engine.Loop`: на каждой границе tool-раунда
(там же, где pending-компакция) движок опрашивает Inject, аппендит
полученные промпты как user-сообщения в сессию и эмитит
`session.UserPromoted{ID}` — маркер снимается в момент, когда модель
увидела сообщение. Контроллер передаёт замыкание, дренящее `promptQueue`
(только пока ход жив, `Alive(gen)`); `finishRun` остаётся фолбэком для
промптов, закрывшихся после последней границы.

## Acceptance Criteria

- [ ] Второй HTTP-запрос к модели во время хода уже содержит queued-текст
- [ ] `UserPromoted` публикуется в момент инъекции, маркер снимается до конца хода
- [ ] Ход остаётся ОДНИМ (нет лишнего третьего запроса)
- [ ] Cancel/Esc: очередь не теряется, дренится фолбэком finishRun
- [ ] Полный go test exit=0, lint 0

## Evidence

- Диагноз: инъекция только в `finishRun` (controller.go), engine-граница
  tool-раунда (engine.go:581) очередь не трогает.
