## Body

**Цель:** несколько живых сессий в одном процессе cozyphi, слева панель «проекты → сессии» (как в Codex app), мгновенное переключение с клавиатуры, человекочитаемые заголовки, которые ставит модель, и такая индикация, что пользователь никогда не путает, в какой сессии он находится и где что-то произошло.

**Референсы (что берём и откуда):** Codex app — левый сайдбар проекты→треды, точка статуса (running / needs approval / done-unread), Cmd+1..9, авто-заголовки, «New thread» в проекте. Claude Code desktop — табы сессий, статусы working / needs input / done, /rename с закреплением пользовательского имени, уведомление о фоновой сессии с её именем. opencode — список сессий с авто-title и бейджем busy. tmux/zellij — нумерованные табы, флаги активности (`*` `!` `~`), Alt+N прыжок по номеру, цвет табов. lazygit — фокусируемая панель с подсказками клавиш в футере, `[`/`]` циклы, цифры для прыжков.

**Принципы:** 1) на экране одна активная сессия, остальные живут в фоне и продолжают стримить; 2) при переключении ничего не теряется — черновик композера, режим (build/plan), позиция скролла, открытые модалки принадлежат своей сессии; 3) любое событие фоновой сессии видно в трёх местах: строка панели, тост с именем и клавишей перехода, desktop-уведомление; 4) заголовок сессии человекочитаемый — его ставит модель (tool `session`, action `set_title`) или пользователь (`/rename`, пользовательский закреплён и моделью не перебивается); 5) всё на клавиатуре, все чорды в keys-таблице (перебиндиваемые, честные к legacy-терминалам: без Ctrl+Shift/Ctrl+Tab, Alt через ESC-префикс, никакого Alt+[ — это CSI); 6) архитектурные инварианты AGENTS.md: без обратных указателей на Editor, конструкторы с параметрами, сборка в cmd/main.go.

**Макет (терминал ≥ 100 колонок):**
```
┃ ▾ cozyphi  ~/src/cozyphi    ┃ #2 · Мультисессия: панель · ~/src/cozyphi (feature/ms) · sonnet-5 · build
┃  1 ◐ Guard: датасет   3m    ┃ ...transcript...
┃  2 ▸ Мультисессия: панель   ┃
┃  3 ? Whisper server   ⚠     ┃
┃ ▾ api  ~/src/api            ┃
┃  4 ● Retry в uploader 12:40 ┃
┃ ▸ Недавние (7)              ┃
┃ + новая (Ctrl+N)            ┃ ┌ composer ────────────────
```
Левая панель — 28 колонок, `ReserveWidth` как у правого сайдбара, на узком терминале (< 100) панель не резервирует место, а открывается поверх по Alt+S. Строка сессии: `N ⟨статус⟩ заголовок ····· возраст`; заголовок проекта — имя каталога + короткий путь, сворачивается. Активная строка подсвечена акцентным цветом сессии (стабильный цвет из палитры 6–8 цветов, тот же цвет у строки-заголовка и рамки композера — периферийным зрением видно, что сессия сменилась). Над транскриптом строка-заголовок активной сессии: номер, название, cwd/ветка, модель, режим.

**Статусы строки (форма + цвет, читаемы без цвета):** `◐` бежит (+ прошедшее время, спиннер в активной), `?` ждёт человека (разрешение / вопрос / continue), `●` есть непрочитанное (ход завершился, пока сессия была в фоне; счётчик), `✗` последний ход упал, `⏸n` очередь промптов, пусто — idle, `◌` закрытая из «Недавних» (можно переоткрыть).

**Клавиши по умолчанию (все в keys-таблице, перебиндиваемые):** Ctrl+T — показать/скрыть панель; Alt+S — фокус в панель с фильтром (набор текста фильтрует, Enter переключает, Esc назад); Ctrl+N — новая сессия в текущем проекте; Alt+Up / Alt+Down — предыдущая/следующая; Alt+1..9 — прыжок по номеру; Alt+` — вернуться в предыдущую активную. Внутри панели: Enter переключить, n новая, N новая в другом каталоге, r переименовать, x закрыть, / фильтр, Esc назад. Палитра Ctrl+K: «Переключить сессию…», «Новая сессия», «Переименовать сессию», «Закрыть сессию». Слэш: /new, /sessions (fuzzy-пикер по всем проектам), /rename <title>, /close.

**Заголовки:** durable-запись `session_title` в jsonl сессии (`{title, source: model|user, timestamp}`), последняя побеждает; `ListSessions`/`SessionMeta` читают её; fallback — первые ≤ 48 символов первого промпта. Tool `session` с action `set_title` (одна строка, ≤ 60 символов, без управляющих символов); системный промпт просит назвать сессию, как только цель ясна, и переименовать при существенной смене темы. `/rename` закрепляет заголовок пользователя — tool отвечает «title is pinned by the user». Отдельного дешёвого вызова модели для авто-заголовка сознательно нет: главная модель называет сессию в первом ходу, fallback — префикс промпта.

**Архитектура — три яруса:** Process (providers, opencode-клиент, jobs manager, usage history, harness settings, notifier, voice, тема, keys) → Workspace на cwd/git-root (project config, mcp pool, lsp manager, memory store, tasks registry, hooks manager) → Session (Controller: engine, stream, gate, mode, watches, plan; собственный Bus; View-бандл: transcript pane, черновик и режим композера, состояние overlays, activity футера, unread/статус). Editor становится мультиплексором: `sessions.Registry` (упорядоченный список, активная, стек last-visited, лимит открытых — 12), каждый кадр дренирует все Bus, рисует только активный бандл; redraw relay срабатывает от любого Bus. Переключение — O(1) подмена активного бандла и перенаправление общего хрома (правый сайдбар SetPlan/SetRuntime, источники футера, settings). Бюджеты: Close каждой сессии ограничен по времени, watches — 8 на сессию.

**Внимание из фона:** ask/question/continue/конец хода/ошибка в неактивной сессии → статус в панели + тост «#2 Whisper server: bash ждёт разрешения — Alt+2» + desktop-уведомление с названием сессии по настроенному режиму. Модалка показывается только когда её сессия активна; переход в сессию возвращает модалку. Voice активен только в активной сессии.

**Проекты:** новая сессия в другом каталоге (N → ввод пути с подсказкой недавних проектов, собранных из заголовков сессий под ~/.cozyphi/session); ресурсы Workspace переиспользуются между сессиями одного проекта; аудит: bash/read/write/find/grep, watches и hooks резолвят пути относительно cwd сессии, никогда — cwd процесса.

**Жизненный цикл:** закрытие бегущей сессии — подтверждение (отмена стрима → Close); закрытая остаётся на диске в «Недавних»; набор открытых сессий, активная и настройки панели хранятся в ui.json (глобально — набор охватывает несколько проектов), восстанавливаются при старте (настройка `sessions.restore`, по умолчанию включена); `-c`/`--resume` добавляют сессию в набор и активируют её.

**Вне скоупа:** split-view двух сессий рядом; синхронизация между процессами; авто-заголовок отдельной дешёвой моделью; drag-and-drop порядка.

**Порядок работ:** multisession-title-entry → multisession-title-tool; multisession-runtime-split → multisession-registry → (параллельно) multisession-sessions-panel, multisession-hotkeys, multisession-switch-cues, multisession-background-attention → multisession-projects, multisession-lifecycle-restore → multisession-hardening.
