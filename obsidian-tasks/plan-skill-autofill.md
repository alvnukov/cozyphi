## Body

**Проблема.** Скиллы шага плана пользователь вводит вручную свободным текстом: поле skills у inject_skill-действия в редакторе плана — строка, которую код токенизирует по запятым и пробелам (`internal/tui/planedit/pane.go:1719-1741`) без сверки со списком существующих скиллов; опечатка молча становится сломанным inject_skill. Каталог скиллов в харнесе при этом есть — editor отдаёт его настройкам (`internal/tui/editor/editor.go:140`, `settings.SetSkills`), и там выбор уже сделан пикером. Главное: подбор необходимо-достаточного набора скиллов под конкретику шага — работа планировщика (модели), а не человека; сейчас она переложена на пользователя, а умолчания plan-scope/type-scope спасают лишь частично, потому что нужный набор зависит от содержания шага, а не только от типа.

**Что сделать.** (1) Автозаполнение: при авторинге плана модель проставляет каждому шагу skill-набор из доступного каталога, исходя из текста и типа шага; наследование умолчаний остаётся базой, поверх которой планировщик уточняет. (2) В редакторе плана заменить свободный ввод пикером по каталогу с fuzzy-фильтром (механика `browse.Jump` уже в ките) и мультивыбором с отметками; ручной ввод имени не из каталога остаётся возможным, но с явным предупреждением. (3) Валидация на сохранении: имя не из каталога подсвечивается, а не проходит молча. Связано с [[adaptive-durable-plan-authoring]].

**Критерий.** Новый план приходит со скиллами на шагах без ручного ввода; в редакторе скиллы выбираются из списка, а не печатаются; несуществующее имя не сохраняется без предупреждения.

**Результат.** Сделано (commit fefcc2c, merge в main bcc1f7c). (1) Автозаполнение планировщиком: схема plan-инструмента теперь вписывает имена установленного каталога в description каждого skills-слота (create steps, update_step, insert_step/supersede_step — «Pick from the installed skill catalog, matching each step's content: …»), материализуясь при сборке инструмента из `deps.Skills`; без каталога схема остаётся байт-в-байт прежней (golden-тест не тронут). Authoring grammar в plan-prompt.tmpl дополнена: «Give each step the least sufficient capability type … — and its skills, picked from the installed catalog» — с ужатием соседних строк бюджет 95–135 слов соблюдён (131). Валидация неизвестных имён на seam-е уже была (`validateSkillNames`). (2) Пикер в редакторе плана: Enter на skills-строке inject_skill-действия открывает новый choice-режим `viewSkills` — мультивыбор по каталогу с отметками `[x]`/`[ ]` (стиль settings-пикера), Enter/Space переключает и держит список открытым, каждый toggle — один шаг undo, Esc фиксирует набор («done», не «cancel»), `/` fuzzy-jump работает — единственный choice-список, достаточно длинный для этого. Имена вне каталога, приехавшие с планом, материализуются отдельными строками с меткой «⚠ not in catalog» и снимаются как обычные; ручной ввод остался через явную строку «other… (type a name)». Каталог приходит из editor тем же `skillNames()`, что у settings (`planedit.SetSkills`); без каталога — прежний текстовый редактор. (3) Валидация на сохранении: имя не из каталога сохраняется, но никогда молча — предупреждение «not in the skill catalog: …» на message-строке и метка `⚠` в пикере и в summary-строке шага (`skills: tdd, ghost⚠`). Новый scope `plan-skills` в каталоге клавиш (футер «toggle/filter/done»), заголовок « Choose step skills ». Тесты: pane_skillpicker_test.go (9 штук: открытие с курсором на первом отмеченном, toggle+сохранение с выжившим off-mark, снятие, отказ пятого скилла, unknown-имя с меткой и снятием, ручной ввод с предупреждением, jump-фильтр, fallback без каталога, undo одного toggle), TestToolDefinitionNamesCatalogSkills в plantool (3 слота + байт-идентичность без каталога), плюс закрепление «skills»/«installed catalog» в plan_grammar_test. Контракт мультивыбора записан в DESIGN.md (раздел Selection and activation) и CHANGELOG.
