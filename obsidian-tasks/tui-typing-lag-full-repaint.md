## Body

**Симптом:** под нагрузкой на ноутбуке символы в cozyphi появляются с опозданием, Claude Code в соседнем окне печатает нормально.

**Причина (замеры 2026-09-24):** каждое изменение композера идёт через `composer/pane.go` OnChange → `View.RequestRefresh` → `vx.QueueRefresh()`, то есть полную перерисовку экрана: ~10–12 KB на клавишу при 120×40 против ~62 B у Claude Code. `App.coalesceWheel` делает то же на каждую прокрутку. `App.Run` рисует кадр после каждого события без склейки. Когда терминал под нагрузкой медленно вычитывает pty, запись кадра блокирует UI-горутину и задержка копится: при чтении 150 KB/s эхо cozyphi растёт 74→281 мс, у Claude Code ровно ~3 мс. CPU не причина: 16× `yes` задержку не поднимает.

**Почему полная перерисовка вообще была:** с первого коммита апстрима — «CJK paste/delete can desync tty wide-glyph columns». Проверка на эмуляторе x/vt показала реальный механизм призраков: когда терминал рисует глиф шире, чем модель xui (✅, ⚡ — EAW=W, а `isWideRune` их не знает), перерисовка этой строки сдвигает её хвост, последняя ячейка переносится автопереносом в столбец 0 следующей строки (`Kept` → ` ept`). Полная перерисовка сверху вниз это маскировала. CJK с совпадающей шириной призраков не даёт.

**Решение:**
- xui/render: кадр пишется с выключенным автопереносом (DECAWM `?7l` … `?7h`), так что запись никогда не переливается на другую строку; строка с не-ASCII глифом перед перерисовкой стирается (EL), чтобы не оставались хвосты при расхождении ширины. Подход ultraviolet (`repaintLine`, `putCellLR`).
- `View.RequestRefresh` убран вместе с методом `SubmitBus`: он никогда не будил цикл, а только помечал весь экран грязным; кадр на клавишу рисует сам обработчик события. Из `coalesceWheel` убран `QueueRefresh`.
- `App.Run`: подряд идущие в очереди клавиши обрабатываются пачкой, Draw между ними сохраняется, в терминал пишется один кадр.

**Вне скоупа:** ширина эмодзи в модели xui (выравнивание хвоста строки после ✅), аппаратная прокрутка транскрипта, редкие QueueRefresh (тема, модель, экспорт, ветка).

**Результат:** ветка `bug/tui-typing-lag-full-repaint`. Замер typelat (кириллица, 60 мс между клавишами, 120×40): при терминале 150 KB/s эхо p50 218 мс → 3,5 мс, p90 323 → 4,0 мс; вывод за сеанс набора 354 KB → 11 KB; без ограничения скорости p50 4,3 → 2,3 мс. Клавиша на настоящем `sessions.View` пишет 308 байт против 10 384 за полный экран (`TestTypedKeyWritesAFractionOfTheScreen`). Эмулятор x/vt: до фикса призраки в 3 из 4 сценариев (✅/⚡ переливаются в столбец 0 следующей строки, у глифа, узкого в терминале, остаётся хвост), после — все 4 чистые. Для тестов в форк xui добавлен `NewWithTTY` (PATCH_NOTES п. 9); рендерер — п. 8. go test/vet по изменённым пакетам и xui, golangci-lint fmt/run по изменённым пакетам — чисто.
