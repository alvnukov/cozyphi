## Body

**Проблема.** Ошибка прогона падает в транскрипт сырым `err.Error()` (`internal/tui/controller/controller.go:1953`) в роли сообщения ассистента. Ни разбора причины — невалидный ключ / rate limit / переполнение контекста / сеть, — ни предложения действия. Прогон просто закончился, ввод уже очищен: чтобы повторить, надо вручную восстанавливать промпт.

**Что сделать.** (1) Классифицировать типовые ошибки провайдера и говорить по-человечески, с действием: «ключ невалиден — /connect», «rate limit — повторить через N секунд», «контекст переполнен — /compact». (2) Рендерить как системную ошибку, а не как текст ассистента (стиль ошибки в транскрипте). (3) Retry-доступность: не терять составленный промпт — вернуть его в composer или дать явное «повторить» (история композера уже хранит отправленное — переиспользовать).

**Критерий.** Для каждой из типовых причин тест проверяет распознавание и текст; после ошибки промпт восстановим одним действием.

**Результат.** Сделано (commit fdd9e3b, merge d6163c2). Классификатор `internal/tui/controller/runerror.go`: overflow → «/compact» (через `llm.IsContextOverflow`), 401/403/invalid key → «/connect», 429/529/rate limit → «подождать» с извлечением retry-after секунд из текста, dial tcp/no such host/refused → «сеть/base URL»; неизвестное — нейтральный заголовок. Сырой текст ошибки всегда сохранён как деталь, последней строкой — подсказка «↑ в композере вернёт промпт» (история композера уже хранит отправленное — одно действие). `AssistantBlock` рендерит `StateError` с маркером «✕ run error» в Destructive — ошибка больше не читается как ответ ассистента. `publishCompactError` использует тот же классификатор (без циклического совета «/compact»). Тесты: runerror_test.go (по причине на кейс + fallback + retry-подсказка), кейсы StateError в assistant_block_test.go. Стандарт зафиксирован в DESIGN.md (Notices): новая поверхность ошибок обязана переиспользовать классификатор, а не печатать `err.Error()`.
