## Body

**Контекст.** Фича microcompaction (коммит edbe292, merge 285e6e2) под давлением контекста заменяет старые крупные tool-результаты в provider view на стаб. Ревью 2026-09-03 нашло дефекты, которые нужно закрыть до того, как на фичу полагаться.

**1. Баг: стабятся результаты текущего раунда.** microCutoff режет только по бюджету keepRecentTokens (около 80 КБ), без учёта границы раунда. Три параллельных bash по 50 КБ в одном раунде: первые два стабятся до того, как модель их увидела; одиночный read view на 1000 строк или отчёт agent_wait больше хвоста стабится на первом же запросе, модель читает «re-run to recover», повторяет и получает тот же стаб. Правило: cutoff не заходит за последнее assistant-сообщение; всё после него verbatim.

**2. Стоимость: сброс prompt cache.** Anthropic-клиент ставит cache breakpoint на хвост последнего user-сообщения. Каждый результат, выпавший из хвоста, меняет старое сообщение на следующем запросе, и префикс перезаписывается целиком. Нужен гистерезис: набор застабленных ID заморожен и применяется всегда, пока сообщения в контексте; расширяется пачкой от старых к новым только когда оценка проекции выше порога напоминания, до порога минус window/10. Множество живёт в Engine под mu, расширение детерминировано (contextStats и запрос дают один результат), устаревшие ID вычищаются на каждой проекции.

**3. Совет в стабе.** «re-run bash to recover» подталкивает повторить мутирующую команду; «re-run question» — переспросить человека; agent_wait повтором не восстановить. Стаб хранит первые строки результата (ограниченно) и совет по тулу; question и agent_wait не стабятся.

**4. Алиасинг.** Microcompact на ранних выходах отдаёт входной слайс (кэш сессии); раньше inferenceContext всегда клонировал. Всегда возвращать копию.

**Вне задачи.** Калибровка оценки bytes/4 по счётчику провайдера (пункт 4 ревью) — отдельно.

**Итог (2026-09-03).** Реализовано Opus-агентом по спецификации, проверено и влито в main: merge 5d8663e (коммит 0cb9f96). `compaction.Microcompact` принимает `MicroPolicy` (KeepVerbatim, Advice, KeepRecentTokens, TriggerTokens, TargetTokens) и замороженный набор ID, возвращает проекцию, отчёт и обновлённый набор; кандидаты только до последнего assistant-сообщения и вне хвоста, расширение от старых к новым до target, устаревшие ID вычищаются, слайс всегда клонируется. Стаб хранит первую непустую строку (до 200 байт, по границе руны) и совет по тулу; для bash и mcp_call совет повторять только read-only вызов. В Engine набор `microStubbed` под mu, providerContext строит policy (trigger = ReminderThreshold, target = trigger − window/10), rearmCompactAdvice сбрасывает набор; `keepToolResultVerbatim` держит verbatim grep, read mode edit, question и agent_wait. Добавлен `Settings.KeepRecentTokens()`, doc-комментарий пакета описывает два слоя, пункт CHANGELOG отредактирован на месте. Замечание из реализации: при окне меньше примерно 45k target оказывается ниже keepRecentTokens, и расширение стабит всех кандидатов сразу (замороженный набор всё равно исключает дрожание). Гейт make fmt-check lint test rc=0 (первый прогон упал на посторонний флейк TestCommandHookSanitizedEnv в internal/hooks, повтор чистый).

## Acceptance Criteria

- Результаты tool-раунда, на который модель ещё не ответила (все RoleTool после последнего assistant-сообщения), никогда не заменяются стабом; тест: три параллельных bash по 50 КБ в одном раунде под давлением остаются verbatim.
- Набор застабленных результатов заморожен по ID tool call: стабы применяются на каждом запросе, пока сообщения в контексте, и расширяются только когда оценка проекции превышает порог напоминания; расширение идёт от старых к новым и останавливается, когда оценка опускается до порога минус десятая часть окна. Устаревшие ID (после macro-компакции) вычищаются.
- Стаб сохраняет первые строки результата (заголовок @read/@file или первую строку вывода, ограниченно по байтам) и даёт совет по тулу: для bash и mcp_call — повторять только read-only вызов; для остальных — повторить с теми же аргументами. Результаты question и agent_wait не стабятся никогда, anchor-несущие read (mode edit) и grep — как раньше.
- Microcompact никогда не возвращает входной слайс: inferenceContext и contextStats получают копию на всех путях.
- contextStats и inferenceContext строят одну и ту же проекцию (одинаковый набор стабов при одинаковом контексте); /context и шапка ctxpane показывают число застабленных результатов как раньше.
- Пункт CHANGELOG про microcompaction в Unreleased отредактирован на месте под итоговое поведение; doc-комментарий пакета internal/session/compaction описывает два слоя (macro cut + micro projection). make fmt-check lint test rc=0.
